# CloudEdgeVLA Setup

This guide creates the Python environment used by the CloudEdgeVLA training and
LIBERO evaluation code. Run all commands from a Linux machine with an NVIDIA
GPU unless a section says otherwise.

## 1. Prerequisites

The reference software stack is:

- Linux
- Python 3.10
- PyTorch 2.3.1, torchvision 0.18.1, and torchaudio 2.3.1
- An NVIDIA driver compatible with the selected PyTorch CUDA build
- A CUDA toolkit with `nvcc` when building FlashAttention from source
- Conda or Miniconda
- Git; Git LFS is also required to download the LIBERO RLDS dataset

Training the 7B backbone requires a high-memory GPU. Paired-frame training runs
fresh and stale backbone passes for every batch, so reduce `batch_size` and use
gradient accumulation if memory is limited. Exact memory use depends on the
checkpoint, attention kernel, image inputs, and distributed configuration.

Check the host before installing:

```bash
nvidia-smi
nvcc --version
conda --version
git --version
```

`nvcc` is only required to compile CUDA extensions such as FlashAttention; the
PyTorch CUDA runtime itself can come from a prebuilt wheel.

## 2. Clone the Repository

```bash
git clone https://github.com/DaojiePENG/CloudEdgeVLA.git
cd CloudEdgeVLA
```

## 3. Create the Conda Environment

```bash
conda create -n cloudedgevla python=3.10 -y
conda activate cloudedgevla
python -m pip install --upgrade pip setuptools wheel
```

Install the project and its declared dependencies:

```bash
python -m pip install -e .
```

The project metadata pins the PyTorch family to 2.3.1/0.18.1/2.3.1 and installs
the OpenVLA-OFT Transformers and DLimP forks used by the code. If your machine
requires a specific PyTorch CUDA wheel, install the matching pinned PyTorch
family first using the command generated by
<https://pytorch.org/get-started/locally/>, then run `pip install -e .`.

For development and formatting tools:

```bash
python -m pip install -e ".[dev]"
pre-commit install
```

## 4. Install FlashAttention

FlashAttention is installed after PyTorch so that its extension is compiled
against the active PyTorch/CUDA environment.

```bash
python -m pip install packaging ninja
ninja --version
MAX_JOBS=4 python -m pip install "flash-attn==2.5.5" --no-build-isolation
```

`MAX_JOBS=4` limits build parallelism and can be lowered on memory-constrained
machines. Verify the core environment:

```bash
python - <<'PY'
import torch
import transformers
import flash_attn
import prismatic

print("torch:", torch.__version__)
print("CUDA runtime:", torch.version.cuda)
print("CUDA available:", torch.cuda.is_available())
print("transformers:", transformers.__version__)
print("flash-attn:", flash_attn.__version__)
print("prismatic:", prismatic.__file__)
PY

python -m pip check
```

`requirements_pinned.txt` records an environment snapshot from a successful
training run. It is useful for comparison and debugging, but it is not a second
installation step to layer on top of an existing environment. Prefer a fresh
environment and the editable install above; mixing old TensorFlow, protobuf,
NumPy, CUDA, or PyTorch packages is a common source of binary incompatibility.

## 5. Install LIBERO

Clone LIBERO next to the CloudEdgeVLA repository and install it into the active
environment:

```bash
cd ..
git clone https://github.com/Lifelong-Robot-Learning/LIBERO.git
python -m pip install -e LIBERO
cd CloudEdgeVLA
python -m pip install -r experiments/robot/libero/libero_requirements.txt
```

For headless evaluation, use EGL rendering:

```bash
export MUJOCO_GL=egl
export PYOPENGL_PLATFORM=egl
```

See [LIBERO.md](LIBERO.md) for the benchmark-specific evaluation notes.

## 6. Download the Training Data

The modified LIBERO RLDS dataset contains the four task suites used by the
training launchers and is approximately 10 GB.

```bash
git lfs install
git clone https://huggingface.co/datasets/openvla/modified_libero_rlds \
  /path/to/modified_libero_rlds
```

Confirm that the directory contains these datasets:

```text
libero_spatial_no_noops
libero_object_no_noops
libero_goal_no_noops
libero_10_no_noops
```

If Git LFS leaves pointer files instead of dataset contents, enter the dataset
directory and run `git lfs pull`.

## 7. Configure Caches and Logging

Choose writable locations with enough disk space:

```bash
export HF_HOME=/path/to/huggingface-cache
export TOKENIZERS_PARALLELISM=false
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
```

For W&B logging:

```bash
wandb login
```

The checked-in launchers include paths and W&B identifiers from the authors'
machines. Before running one, edit its configuration block and replace:

- `VLA_PATH`
- `DATA_ROOT_DIR`
- `RUN_ROOT_DIR`
- `RESUME_ROOT_DIR`, when present
- `HF_HOME`
- W&B entity and project arguments

The local launchers initialize from a local task-combined OpenVLA-OFT checkpoint
by default. Download or prepare that checkpoint and set `VLA_PATH` to its actual
location. Do not accidentally initialize a fresh experiment from an older
frame-delay run checkpoint.

## 8. Smoke Tests

Run the temporal-alignment unit test before starting a long training job:

```bash
python -m pip install pytest
pytest -q tests/test_frame_delay_alignment.py
```

Check that the training CLI imports successfully:

```bash
python vla-scripts/finetune.py --help
python experiments/robot/libero/run_libero_eval.py --help
```

These commands validate imports and argument registration; they do not download
the 7B model or run a GPU training step.

## 9. Start Training

Activate the environment and start a run, passing the three required paths:

```bash
conda activate cloudedgevla
VLA_PATH=/path/to/openvla-7b-oft-finetuned-libero-spatial-object-goal-10 \
DATA_ROOT_DIR=/path/to/modified_libero_rlds \
RUN_ROOT_DIR=/path/to/runs \
NUM_GPUS=8 bash scripts/train_libero_all.sh
```

Add `--suite spatial|object|goal|10` to train one LIBERO suite instead of the
merged four-suite mixture, and `--resume` to continue from the latest checkpoint
of the same run. `BATCH_SIZE`, `MAX_STEPS`, `SAVE_FREQ`, `SHUFFLE_BUFFER`, and
`WANDB_ENTITY` are environment variables documented at the top of the script.
See the README for the full hyperparameter table.

## Troubleshooting

### FlashAttention build failure

Confirm that `which nvcc`, `python -c "import torch; print(torch.version.cuda)"`,
and the NVIDIA driver describe a compatible toolchain. Then retry from the
active environment:

```bash
python -m pip cache remove flash_attn
MAX_JOBS=2 python -m pip install "flash-attn==2.5.5" --no-build-isolation
```

### CUDA out of memory

Lower `BATCH_SIZE` in the launcher and raise `GRAD_ACCUM_STEPS` to preserve the
effective batch size. Paired-frame training intentionally performs two
backbone forwards, so OpenVLA-OFT's single-path memory estimates do not directly
apply.

### LIBERO cannot create a rendering context

Set `MUJOCO_GL=egl` and `PYOPENGL_PLATFORM=egl` before evaluation. Also verify
that the NVIDIA driver is visible inside the shell or container.

### TensorFlow, protobuf, or NumPy import errors

Create a fresh Python 3.10 environment and reinstall with `pip install -e .`.
Avoid combining the environment with unrelated TensorFlow or robotics stacks.
Use `python -m pip check` to identify incompatible installed versions.

### Checkpoint rejected by the evaluation launcher

For a local checkpoint directory, `scripts/eval_libero_delay_sweep.sh` expects
merged weights with `model.safetensors.index.json`, `dataset_statistics.json`,
exactly one `action_head--*_checkpoint.pt`, and exactly one
`proprio_projector--*_checkpoint.pt`. To skip local bookkeeping entirely, pass
the Hub repo id `DaojiePENG/cloudedgevla-libero-spatial-object-goal-10` instead
of a directory. Either way the checkpoint must match the evaluation arguments:
LoRA rank, number of camera inputs, proprioception, and action-head settings.
